# P1 — Modelo de previsibilidade — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Previsão que acerta por componente (não por compensação), calculável "como se fosse" qualquer data, com teste contra o passado.

**Architecture:** As funções puras da projeção saem de `src/lib/queries.ts` para `src/lib/previsao.ts` (testáveis sem banco) e ganham a data de referência `hoje`. `getProjecaoBase(resp, hoje)` em `queries.ts` passa a receber `hoje` em todo SQL. Receita vira soma de **fontes recorrentes** (mediana); fatura vira **vencimento real** (histórico da Pluggy / `fatura_id` / deslocamento aprendido). `queries.ts` reexporta os nomes, então páginas, API e Diagnóstico não mudam.

**Tech Stack:** TypeScript, Next 14, `pg`, vitest 3, esbuild.

**Spec:** `docs/superpowers/specs/2026-10-09-p-previsibilidade-design.md`

## Global Constraints

- Repositório **público**: nenhum valor real de lançamento, nome de terceiro ou id em teste, plano ou commit. Testes usam números sintéticos.
- Formatos públicos que **não mudam**: `ProjecaoMes`, `Ritmo`, `ReceitaPrevista` (`nome`, `valor`, `diaTipico`, `responsavel` — ganha `fonte`), `CompromissoManual`, `SaldoConta`, `getPrevisaoResumo` (API dos bots).
- `computeProjecao(base, horizonte, hoje?)` e `computeRitmo(base, atual, hoje?)`: `hoje` opcional, padrão `currentDateSP()` — chamadores atuais não mudam.
- Fuso: São Paulo; `hoje` é `'AAAA-MM-DD'`.
- Critério de aceite (spec): em cada um dos 3 últimos meses fechados, erro de receita ≤ R$ 400, de fatura ≤ R$ 400, do total ≤ R$ 500, e nenhum componente pior que a linha de base.
- Commit com `git commit -F arquivo`, terminando com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- **Salário em duas partes** (mesma fonte, dias 5 e 20): no mês corrente, depois da primeira parte, a segunda ainda tem que aparecer como "ainda entra" (teste na Task 3).
- **Fonte sem documento** (banco que não manda CPF/CNPJ): agrupa pela descrição sem dígitos e ainda é reconhecida como recorrente (Task 3).
- **Mês sem fatura no histórico** (cartão novo, ou futuro): cai para as compras lançadas + média, sem `NaN` nem `undefined` (Task 4).
- **Compra do fim do ciclo de cartão com vencimento pelo deslocamento aprendido** (Neon/Santander: `fatura_prevista` é o mês anterior ao vencimento) (integração, Task 4).
- **`hoje` no passado** não pode enxergar lançamento que só existiu depois (integração, Task 1).
